# Synerion Attendance Auto-Reporter ⏱️

כלי אוטומטי המיועד לעובדי קבלן / מיקור חוץ (כגון עובדי פרולוג'יק, קומבלק וחברות נוספות): הכלי קורא את קובץ ה-PDF החתום של דיווח השעות (מהמערכת הממשלתית/הראשית) ומדווח אוטומטית את השעות במערכת הנוכחות של מעסיק הליבה (**Synerion Cloud**), ללא צורך בהקלדה ידנית כפולה.

## 🎯 מה הבעיה שהכלי פותר?

כעובדי קבלן, אנו נדרשים לדווח פירוט שעות ומשימות במערכת הממשלתית, להפיק PDF, להחתים מנהל/ת ולשלוח למעסיק. לאחר מכן, נדרש דיווח ידני כפול של אותן השעות בדיוק גם במערכת השכר והנוכחות של חברת הקבלן (במערכת Synerion Cloud).

**הכלי הזה מייתר את ההקלדה הידנית השנייה:** הוא טוען את קובץ ה-PDF המאושר ומזין את השעות אוטומטית ל-Synerion.

## 🚀 הוראות שימוש צעד-אחר-צעד

1. **הורדה:** נכנסים ללשונית [Releases](../../releases) בעמוד זה ומורידים את קובץ ה-`ZIP` העדכני.
2. **חילוץ:** פותחים/מחלצים את קובץ ה-`ZIP` לתיקייה במחשב.
3. **הרצה:** מפעילים בדאבל-קליק את הקובץ **`התחל כאן`** ומחכים לפתיחת המסך בדפדפן.
4. **הגדרה ובחירת קובץ:**
   - בודקים ומעדכנים בראש המסך את כתובת ה-Synerion של חברת הקבלן שלכם (למשל של פרולוג'יק או קומבלק).
   - לוחצים על **בחירת קובץ** ובוחרים את קובץ ה-PDF החתום של השעות.
   - לוחצים על כפתור **דיווח שעות**.
5. **התחברות והמתנה:**
   - בחלון ה-Synerion שייפתח, מכניסים שם משתמש וסיסמה.
   - ממתינים לסיום הריצה האוטומטית.
6. **בדיקה והשלמה:** 
   - החלון נשאר פתוח בסיום כדי שתוכלו לוודא שהשעות נקלטו כראוי ולהשלים ידנית דיווחי חופשה/מחלה במידת הצורך.

## 🛠️ הורדה, פיתוח ובנייה מקומית

כדי להמשיך לפתח את קוד המקור, צריך מחשב Windows עם Python ו-Git. הורידו את הפרויקט מ-[GitHub](https://github.com/RivkaAltshuler/synerion_attendance). מומלץ לשכפל עם Git כדי שיהיה קל למשוך עדכונים ולשתף שינויים:

```powershell
git clone https://github.com/RivkaAltshuler/synerion_attendance.git
cd synerion_attendance
```

אפשר גם לבחור **Code → Download ZIP** בעמוד הפרויקט ולחלץ את הארכיון. שימו לב: ה-ZIP של קוד המקור מיועד לפיתוח; ה-ZIP בלשונית **Releases** מיועד להרצת התוכנה בלי סביבת פיתוח.

### הכנת סביבת הפיתוח (פעם אחת)

תהליך ה-CI של הפרויקט נבנה עם Python 3.11, ולכן מומלץ להשתמש בו כדי להתאים לסביבת הבנייה האוטומטית. הפקודה `py -0p` היא רק בדיקה אופציונלית שמציגה גרסאות Python המותקנות דרך Windows Launcher; אם מתקבלת הודעה ש-`py` אינו מזוהה, דלגו עליה ובדקו עם `python --version`:

```powershell
py -0p
python --version
```

אם `py -0p` עובד ומציג Python 3.11, השתמשו בפקודה הראשונה למטה. אם `py` לא זמין אבל `python --version` מציג Python 3.13 (או גרסה אחרת מותקנת), החליפו אותה בפקודה החלופית שמיד אחריה. פתחו PowerShell בתיקיית הפרויקט והריצו את מסלול אחד בלבד:

```powershell
py -3.11 -m venv .venv
```

חלופה כאשר `py` אינו מזוהה, אבל `python --version` עובד:

```powershell
python -m venv .venv
```

אחרי שאחת הפקודות יצרה בהצלחה את `.venv`, הריצו:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install pyinstaller
Test-Path .\.venv\Scripts\python.exe
```

הפקודה האחרונה צריכה להחזיר `True`. אם `python --version` גם אינו עובד, התקינו Python (מומלץ 3.11) וסמנו בהתקנה את האפשרות להוסיף אותו ל-PATH, או הפעילו מחדש את PowerShell אחרי ההתקנה. אם משתמשים בגרסה שאינה 3.11, הבנייה המקומית עשויה לעבוד אך סביבת ה-CI עדיין נבדקת עם 3.11.

**חשוב:** יש ליצור את `.venv` לפני התקנת PyInstaller או הרצת קובץ הבנייה, ולהתקין את PyInstaller באמצעות ה-Python שבתוך `.venv`. הודעת `[שגיאה] סביבת הפיתוח לא מוכנה` פירושה ש-`build_release.bat` לא מצא את הקובץ `.venv\Scripts\python.exe` — בדרך כלל כי הסביבה עוד לא נוצרה, נוצרה בתיקייה אחרת, או שפקודת יצירתה נכשלה. התקנת Python או PyInstaller מחוץ לסביבה הזו לבדה לא פותרת את הבדיקה הזאת. אם נוצרה סביבה חלקית או פגומה, מחקו את תיקיית `.venv` וצרו אותה מחדש מהתיקייה הראשית של הפרויקט.

### הרצה ובדיקה של קוד המקור

```powershell
.\.venv\Scripts\python.exe .\web_app.py
```

פתחו `http://127.0.0.1:5000` בדפדפן. לעצירת השרת לחצו `Ctrl+C` בחלון PowerShell. אם פורט 5000 כבר תפוס, עצרו את התהליך הישן או שנו זמנית את הפורט בקריאת `app.run`.

### בניית EXE ו-ZIP להפצה

אחרי הכנת `.venv`, הריצו מתוך תיקיית הפרויקט:

```powershell
.\build_release.bat
```

בסיום, קובצי ה-EXE יופיעו ב-`dist`, ותיקיית ההפצה וקובץ ה-ZIP יופיעו תחת `release`. הקובץ הזה משמש גם את GitHub Actions בתהליך ה-CI; אפשר להריץ אותו באותה צורה גם במחשב מקומי.
